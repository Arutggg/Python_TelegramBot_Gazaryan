## Что умеет бот

Многопользовательский календарь в Telegram. Каждый пользователь регистрируется
и работает только со своими событиями: создаёт, смотрит, редактирует и удаляет их.
События хранятся в PostgreSQL.

| Команда | Что делает |
|---|---|
| `/start`, `/help` | Список команд |
| `/register` | Регистрация (без неё остальные команды недоступны) |
| `/create_event` | Пошаговое создание события: название → дата → время → описание (`/skip` — без описания) |
| `/events` | Все события пользователя по дате и времени |
| `/read_event [название]` | Показать событие |
| `/edit_event` | Пошаговое редактирование; `-` оставляет поле без изменений |
| `/delete_event [название]` | Удалить событие |
| `/cancel` | Прервать текущий диалог |

Формат даты — `ДД.ММ.ГГГГ`, времени — `ЧЧ:ММ`. Неверный ввод бот просит повторить,
не сбрасывая диалог.

## Как устроено

```
bot.py             обработчики команд и диалогов, запуск бота
event_calendar.py  класс Calendar — CRUD событий в PostgreSQL
users.py           класс Users — регистрация пользователей
db.py              подключение к базе и создание таблиц
tests/             тесты на pytest (календарь и сквозные диалоги бота)
```

- **Многопользовательский режим.** Пользователь хранится в таблице `users` по Telegram ID,
  у каждого события есть `user_id`. Все запросы фильтруют по `user_id`, поэтому
  пользователь не может прочитать, изменить или удалить чужое событие.
- **Состояние пользователя** отслеживается через `ConversationHandler`: бот помнит,
  на каком шаге диалога находится каждый пользователь, а черновик события хранится
  в `context.user_data`. Диалоги разных пользователей не пересекаются.
- **Безопасность:** все SQL-запросы параметризованы, токен и пароль от базы лежат
  в `secrets.py`, который не попадает в git.

Схема базы:

```sql
users  (telegram_id bigint PK, username, first_name, registered_at)
events (id serial PK, user_id bigint FK -> users, name, date, time, details)
       UNIQUE (user_id, name)
```

## Запуск

Нужен **Python 3.11 или 3.12**: `python-telegram-bot==13.13` не работает на Python 3.13+.

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и получите токен.
2. Создайте базу в PostgreSQL: `createdb -U postgres calendar_bot`.
3. Скопируйте `secrets_example.py` в `secrets.py` и впишите токен и данные для подключения к базе.
4. Запустите бота: `python bot.py`. Таблицы создадутся автоматически.

## Тесты

Тестам нужна отдельная база (по умолчанию `calendar_bot_test`, пользователь и пароль `postgres`;
можно переопределить переменными `TEST_DB_HOST`, `TEST_DB_NAME`, `TEST_DB_USER`, `TEST_DB_PASSWORD`).

```bash
createdb -U postgres calendar_bot_test
pytest
```

Тесты проверяют CRUD календаря, изоляцию пользователей и полные диалоги с ботом
(сообщения проходят через настоящие обработчики, без обращения к Telegram).
